- 중요 산업 변화: 24시간 검증 완료 후 즉시 Telegram 발송. 일반 산업 변화: 한국시간 06·10·14·18시 브리프, 각 회차 90분 안에 검증된 추가 기사 처리.
- 핵심 소스 2분, 전체 소스 5분, 실제 Gmail 플러그인 10분 증분 조회. 주기는 시작 목표이며 네트워크·심사 중 같은 수집기 중복 실행 금지. 게시 즉시 push나 수분 내 도착 보장은 아님.

- Newsflow-V12-Continuous 로그인 예약작업이 pythonw 상시 실행. V11 작업은 비활성화 보존. Codex pc 예약은 매일 06시 상태 점검만 수행, 중복 발송 금지.
- PC 전원·로그인·인터넷·Codex 인증/사용량 필요. 화면 꺼짐은 가능하나 절전·로그아웃·종료 중 실행 불가.

## 토큰 검증 — 비용 절감률과 구분

- 과거 8개 실행의 관련 발송이력 입력: 722,189 → 55,009 bytes, 92.4% 감소. **해당 입력 부분만의 감소**이며 전체 토큰/청구액 92.4% 절감이라는 뜻 아님. 최종 발송 guard는 전 기간 실제 본문 전체 비교 유지.
- 실제 Gmail 무신규 1회: 입력 38,904 tokens, cached 25,856, output 175. 과거 무신규 중앙값 약 58,380 input 대비 약33% 축소. 새 프로필의 초기 uncached가 감소한 것은 아니므로 비용 절감률은 운영 후 비교 필요.
- 기존 Gmail 프롬프트의 처리ID 220개 → 해당 증분 조회 범위 0개, 전체 처리이력은 로컬 DB에 유지. 최신 12개 캐시 메일 링크 176 → 163개, 개인정보/로그인/공유 등 비기사 13개 제거.
- work/v11/usage.db와 각 execution.json에 호출 수·input/cached/output·프롬프트 크기·도구 호출 기록. 큰 input 합계를 전부 신규 소비로 표현하지 않음. 초기 테스트 호출도 구분해서 해석 필요.
- 첫 실운영11개 후보 검증은 반복 검색18회로 input1,363,136/cached1,255,424/output7,445 발생. 이력 압축만으로 전체 비용 절감을 달성했다고 결론내릴 수 없는 증거. 분석 묶음을12→4개로 축소하고, 발행사 검색+독립 대체 경로 이후 새 단서 없는 검색 변형 반복을 금지. 실제 새 단서는 검증하며 원문 미확인은 완료로 둔갑시키지 않음. 최종 총비용 효과는 동일 기사량 기준 운영 데이터 비교 필요.
- 최종 설정의 첫 실제 소규모 분석(11:52:30~11:53:52 KST):4개 모두 검토완료 ACK, 계약 검증 오류0, 도구 호출5회, input184,990/cached143,232/output2,778. work/v11/reviews/4260702a1cbf462e976e5bfab1815309. 서로 다른 기사를 처리한 표본이므로 이 수치만으로 비용 절감률을 확정하지 않음. 다음 묶음은 서비스가 계속 처리 중.
